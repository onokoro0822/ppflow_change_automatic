# 所在地ベース流入の訂正とアクセシビリティ試作

確認日: 2026-10-13 JST

## 結論の訂正

従来の「中村区への流入が増えない」は、出力gcode（上位MNLで選択した市区町村）の集計についての結果だった。
`ActGenerator`は店舗を選んだ後も`GLonLat(fac, city.getId())`を返すため、店舗所在地の行政コードとは一致しない。
境界をまたぐ共有メッシュでは、別の区の店舗へ配分が移る。したがって選択都市の到着数不変から、実際の店舗所在地への到着不変を推論してはいけない。
以下の所在地は小売入力ADDCDであり、実測人流や独立した境界ポリゴンによる検証ではない。

下限〜上限は未対応・行政コード競合等の分類不確実性を残した保守的範囲。統計的な信頼区間ではない。
同じ不明座標で自宅出発条件も不変のイベントは差分で相殺し、同座標に行政コードが競合する場合は不確実性を残す。
人・時刻・目的で対応付けし、未対応のイベントも捨てない。

試作seed42では他地区の店舗から中村区へ35件入り、9件出た。転入前店舗は西区30・中区3・あま市1・清須市1。
転出後は西区6・東浦町1・清須市1・中川区1。不確実な変化1件を含めて純増26〜27件。
店舗所在地が中村区かどうかと選択都市の一致しない買物は10829→10823件、買物全体39877件。
所在地不明252→253件、行政コード競合0件。区外自宅出発以外の系列にはこの流入結論を一般化しない。

研究室モデル（β=0）の9/29代表3ケースも再集計した。選択都市は896→896だが、
区外自宅→中村区店舗はfacility_100xで342→348（純増6）、mesh_10xで342→410（純増67〜68）、
combined_mesh_10x_facility_10xで342→409（純増66〜67）。10ケース全部を再集計したわけではない。
**従来モデルでも所在地ベースの流入増はあり、新式だけが流入を生んだという結果ではない。**

## 新式の実装とPT比較

市区町村選択に`log(1 + Σ E_m^p / max(d(o,m),1km)^q)`を加える任意オプションを実装した。
距離は出発都市の代表点とメッシュ中心。完全なnested logitではなく、アクセシビリティ説明変数の試作。
`--shopping-accessibility p,q`の既定値1,0は旧市区町村合計と同じ経路。

53出発地単位をseed13でtrain31/validation11/test11に分割。12候補からvalidationでp=0.5,q=2を選び、
選択後にtestを評価。初期値は中立値[0,1,1,1,1]。全PT推定係数を初期値にした初版は撤回・再推定し、選択候補と最終係数は同じだった。
平均test対数確率は−1.289513、trainだけで推定した旧式は−1.329815（test266017トリップ）。
ただしPTは物理地区、Python代理MNLは選択都市を予測するため、この差だけでは実生成の所在地ODでの優位性を証明できない。
全PT再推定値をJavaへ渡した実行は将来計画の試算であり、独立test評価とは区別する。

β=0.921875、倍率=0.3359375,-0.09375,-3.90625,0.109375、区内raw、p=0.5,q=2。
施設到着355件（目標360）、施設出発地TVD0.374626。seed42のみで、新式のseed安定性・外部施設検証は未完了。
