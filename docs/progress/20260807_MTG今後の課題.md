## 1. MTG後の結論

今後の中心は、名鉄百貨店の閉店後に旧利用者がどこへ移ったかを精密化することではなく、
**名鉄跡地へ異なる施設を整備したとき、どのような人が何人来訪し、どのような人流になるかを
複数シナリオで生成・比較すること**である。

2026年8月6日までに作成した閉店後再配分は、トリップチェーン変更処理を一度通した
技術的な初期実験として保存する。ただし、旧本店境界、1,977人の精密化、閉店後の代替先推定を
直近の中心課題にはしない。

MTGで最優先とされたのは、施設計画A・B・Cごとに、次の2点を根拠付きで設定することである。

1. 1日当たりに想定する来訪者の絶対人数
2. 年齢層など、来訪者属性の構成比

施設種別によって来訪者数とターゲット層が異なるため、この設定が人流生成より前に必要であり、
研究の中心部分になる。文字起こし14:49〜14:55でこの方針が示された。

## 2. 8月13日の中間確認までに行うこと

中間確認は2026年8月13日18時〜19時、次回定例MTGは8月26日11時の予定である。
8月13日までの最小成果物は、実装ではなく、次の「シナリオ需要設定表」とする。

### 2.1 計画A・B・Cの施設タイプを決める

MTGではA・B・Cの具体的内容までは決定していない。大規模商業施設、ホテル、公園、
家電量販店などが例として挙げられたが、これらをそのまま採用する決定ではない。

まず3案程度について、次を明記する。

- 主用途と副用途
- 延床面積または用途別床面積
- 営業時間
- 主要なサービス・テナント構成
- 想定する利用目的
- 単独施設か複合施設か

最初は複雑なテナント単位ではなく、用途差が比較できる粒度に留める。

### 2.2 来訪者数の根拠を集める

各施設タイプについて、次の順で根拠を探す。

1. 国・自治体・業界団体の需要予測マニュアルや原単位
2. 建築・都市計画・交通計画分野の既存研究
3. 類似施設が公式に公表する来館者数と延床面積
4. マーケティングレポート等の補助資料

MTGでは、床面積に原単位を掛けて1日来訪者を求める大規模商業施設向けマニュアルが
例示された。文字起こし上の資料名は誤認識の可能性があるため、正式名称を確認してから引用する。

初版では、次のような簡易式でよい。

```text
想定1日来訪者数 = 用途別床面積 × 用途別来訪原単位
```

値を一点に固定せず、低位・基準・高位の3水準を持たせる。

### 2.3 来訪者属性の構成比を設定する

施設タイプごとに、取得可能な範囲で次を調べる。

- 年齢構成
- 就業状態または職業構成
- 来訪目的
- 来訪時間帯
- 滞在時間
- 居住地・商圏距離
- 交通手段分担
- 平日・休日差

ただし、現在のPseudo-PFLOW入力には年齢・性別がない。現状で直接利用できる主な属性は、
就業状態、移動目的、時間、距離、交通手段、前後活動である。年齢構成をモデルに使う場合は、
追加データを取得するか、人口統計等から属性を合成付与する別工程が必要になる。

### 2.4 一枚の根拠表にまとめる

8月13日時点では、少なくとも次の列を持つ表を作る。

| 項目 | 内容 |
| --- | --- |
| シナリオ | A・B・C |
| 施設用途 | 主用途・副用途 |
| 規模 | 延床面積・用途別床面積 |
| 来訪原単位 | 人／平方メートル／日など |
| 1日来訪者 | 低位・基準・高位 |
| 属性構成 | 根拠が得られた分類ごとの割合 |
| 時間分布 | 開館時間・ピーク時間 |
| 商圏 | 想定距離・市内外割合 |
| 出典 | 資料名・ページ・基準年 |
| 確度 | 実測・公表値・既存研究・仮定 |

この表ができた時点でSlack等により関本先生へ共有し、次のMTGまで待たずに確認する。

## 3. 需要設定後の人流生成

施設計画と来訪需要が決まった後は、次の順で実装する。

1. シナリオ別の1日来訪者数と属性構成を入力する。
2. Pseudo-PFLOW母集団から、属性、距離、時間、前後活動が条件に合う人物・トリップを抽出する。
3. 来訪者数の制約を満たすように対象者を確率的に選ぶ。
4. 新施設への活動を既存のアクティビティチェーンへ挿入または置換する。
5. 前後の出発地・目的地・時刻を整合させ、ODを作る。
6. 交通手段を推定する。
7. 道路・鉄道ネットワーク上で最短経路等を求め、軌跡データにする。
8. 軌跡化した後にMobmapで可視化する。
9. A・B・Cについて人数、属性、時間帯、交通手段、経路混雑を比較する。

現状のMobmap表示はOD点間の直線補間である。MTGでは、直線表示だけでは考察材料が少ないため、
経路探索を行って軌跡にした後にMobmapを使うよう指摘された。

## 4. 恣意性を抑える方法

一つの評価関数に適合する計画だけが高評価になる問題に対しては、計画案を一つの総合点で
順位付けするのではなく、外部根拠で需要条件を先に定め、複数指標を並べて比較する。

- 施設タイプ別の来訪者数と属性は外部資料から設定する。
- 来訪者数は低位・基準・高位で感度分析する。
- 施設案の比較指標を、総来訪者数、時間帯別流入、交通手段、商圏、経路負荷などに分ける。
- 同じ一つの「魅力度スコア」で全用途を評価しない。
- 仮定、推定値、実測値を表の上で区別する。

これにより、アルゴリズムが計画案の優劣を恣意的に決めるのではなく、与えた施設需要が
周辺人流へどのような結果をもたらすかを比較する研究として整理できる。

## 5. 母集団の拡大

現在の入力は名古屋市16区で、市外居住者を欠く可能性が高い。名古屋駅の日常利用者を
表現するため、市内居住者と市外居住者の構成比を公的統計等で確認する。

その結果、市外利用者を無視できない場合は愛知県全体へPseudo-PFLOW入力を拡大する。
観光客まで同時に精密化すると作業が広がるため、初版では日常的な名古屋駅利用者を優先し、
観光客は不足分または別シナリオとして扱う。

愛知県全体への拡大はMTGで候補として示されたが、必須範囲として確定したわけではない。
構成比と計算負荷を確認して決める。

## 6. 優先順位

### 最優先

1. 計画A・B・Cの施設タイプと規模を決める。
2. 用途別の来訪原単位・公表来訪者数を調べる。
3. 1日来訪者数を低位・基準・高位で設定する。
4. 属性・時間帯・商圏・交通手段の構成比を根拠付きで設定する。
5. 8月13日の確認用に一枚の根拠表へまとめ、事前に共有する。

### 次段階

6. 現在のデータで利用可能な属性と、追加が必要な年齢等を整理する。
7. 必要性を確認したうえで母集団を愛知県へ拡大する。
8. シナリオ別の来訪者抽出・活動チェーン挿入を実装する。
9. 交通手段とネットワーク経路を生成する。
10. A・B・Cの人流を複数指標で比較する。

### 現時点で優先しない

- 1,977人を旧本店の実来訪者数へ近づける精密化
- 閉店後の代替先644地点の全件施設名付与
- Huff型閉店後再配分モデルのパラメータ調整
- OD直線だけを使ったMobmap表示の追加調整
- UIの改善

これらは不要になったわけではなく、既存実装・検討履歴として保存する。
