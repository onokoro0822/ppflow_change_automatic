# 商業・宿泊・エンタメ施設の来訪者数予測方法

作成日: 2026-08-13 JST

## 0. 結論

3施設には同じ「床面積当たり来訪者数」を使わず、需要を直接生む規模変数に応じて、次の3種類の
予測器を使う。

| 施設 | 需要を決める主な規模変数 | 基本予測器 | 予測する人数の単位 |
|---|---|---|---|
| 商業施設 | 小売店舗面積 | 店舗面積×日来店客数原単位 | 来店回数/日 |
| 宿泊施設 | 客室数 | 客室数×客室稼働率×1利用客室当たり人数÷平均連泊数 | 新規チェックイン人数/日 |
| エンタメ施設 | 席数・収容人数、開催本数 | 開催ごとの収容人数×実入場率を合計 | 入場者数/日 |

3案を比較するときは、最終的に「その日に外部から施設へ到着する人数」へ揃える。ただし、元の
来店回数、人泊、入場者数も消さずに保存する。従業員、搬入、商業・飲食の併用者は別に算定し、
単純加算による二重計上を避ける。

## 1. 商業施設

### 1.1 基本式

大規模小売店舗立地法の指針に基づき、小売店舗面積から日来店客数を算定する。

```text
N_retail = A(S) × S

S: 小売店舗面積（千m²）
A: 店舗面積当たり日来店客数原単位（人/千m²）

人口40万人以上の商業地区:
S < 20  : A(S) = 1,500 - 20S
S >= 20 : A(S) = 1,100
```

例として小売店舗面積20,000m²なら、

```text
N_retail = 1,100 × 20 = 22,000来店/日
```

となる。ここで使うのは延床面積ではなく、**小売業を行う店舗面積**である。共用部、ホテル、
オフィス、映画館等を含む建物全体の面積を掛けない。

### 1.2 本研究での使い方

22,000人を確定値にせず、公的原単位による基準値とする。名古屋駅接続、用途構成、店舗面積、
駐車場規模が近い類似施設3件以上について、公式来館者数または現在の位置情報集計を集め、次の
補正倍率を求める。

```text
k_r = 類似施設rの観測日来店客数 / [A(S_r) × S_r]

N_retail,adjusted = A(S_new) × S_new × weighted_mean(k_r)
```

類似施設間の補正倍率の分布から低位・基準・高位を作る。根拠なしの一律±20%は最終値に使わない。
平日、休日、開業初期、通常期を分ける。

### 1.3 根拠と限界

- 経済産業省の指針は、店舗面積当たり日来店客数原単位を提示している。
- 国土交通省「大規模開発地区関連交通計画マニュアル」は、商業施設の交通量を用途別面積、
  駅距離、PT調査、類似施設で検証する考え方を示している。
- 原単位の基礎データが古く、駅直結性、EC普及、テナント構成を直接表さないため、類似施設による
  現在値への校正が必要である。
- 日来店客数は必ずしもユニーク人物数ではない。同一人物の同日複数来店を区別して保存する。

### 1.4 Pseudo-PFLOWへの接続

初版は品質条件を満たす目的100（買い物）の既存トリップから、目標人数と属性構成に合う人物を
非復元抽出し、目的地を新施設へ置換する。追加誘発された買い物は、既存トリップ置換とは別モデルにする。

## 2. 宿泊施設（ホテル）

### 2.1 基本式

宿泊施設では、「その日に滞在している宿泊者」と「その日に新しく到着する人」を分ける。

```text
G_night,avg = R × o_avg × g_avg
N_checkin,avg = G_night,avg / L_avg

期間集計を使う場合:
N_checkin,avg = total_guest_nights / mean_length_of_stay / number_of_days

R     : 販売可能客室数
o_avg : 対象期間の平均客室稼働率
g_avg : 1利用客室当たり平均宿泊人数
L_avg : 平均連泊数
```

- `G_night`: 宿泊人泊/日。平均的にその日に宿泊している人数
- `N_checkin`: 新規チェックイン人数/日。人流へ追加する外部到着者数

観光庁「宿泊旅行統計調査」2025年確定値では、愛知県のビジネスホテル客室稼働率75.4%を
基準候補にできる。500室なら、

```text
G_night,avg = 500 × 0.754 × g_avg
N_checkin,avg = 500 × 0.754 × g_avg / L_avg
```

となる。これは稼働率が期間中おおむね安定している場合の日平均である。特定日のチェックイン人数は、
予約・到着・出発実績または曜日・季節別の到着率から予測する。`g_avg`と`L_avg`を取得せずに
490人/日などと確定しない。

### 2.2 宿泊以外の外来者

ホテル全体の外部来訪者は、宿泊客だけではない。次の用途を別々に算定する。

```text
N_hotel_external
  = N_checkin
  + N_restaurant_external
  + N_banquet_conference
  + N_other_external
  - N_cross_use
```

- レストラン外来客: 席数×回転数×稼働率、または類似ホテルの実績
- 宴会・会議客: 会場定員×開催本数×実参加率
- `N_cross_use`: 宿泊客が館内飲食・宴会も利用した重複分
- 従業員と納品・業務来訪は、来訪客ではなく交通負荷の別項目として保存

### 2.3 本研究での校正

観光庁統計または類似ホテルから、ホテル種別・地域・月別に次を取得する。

1. 客室稼働率 `o`
2. 延べ宿泊者数÷利用客室数による `g`
3. 延べ宿泊者数÷実宿泊者数による平均連泊数 `L`
4. 国内出張、国内観光、外国人の構成
5. 曜日・月・繁閑期

低位・基準・高位は、閑散期、平年、繁忙期の実績から作る。ビジネスホテルという名称だけで
宿泊者全員を出張者とみなさない。

### 2.4 根拠と限界

- 観光庁「宿泊旅行統計調査」は、客室稼働率、利用客室、延べ・実宿泊者等を提供する。
- 同調査の記入要領は、実人数を直接集計できない場合に、延べ人数を平均連泊数で割る考え方を示す。
- 国交省マニュアルはホテルを特殊用途とし、室数に応じた需要を類似事例から予測するよう示す。
- 現在のPseudo-PFLOWは24時間1日で宿泊目的コードを持たないため、業務500をホテルへ単純置換してはならない。

### 2.5 Pseudo-PFLOWへの接続

チェックイン、宿泊、翌日チェックアウトを日跨ぎの活動系列として新設する。現在の1日データだけで
は実装できないため、日跨ぎ人物データまたは連続2日以上の合成人流を用意してから処理する。

## 3. エンタメ施設

### 3.1 施設タイプを先に限定する

「エンタメ施設」は一つの式で扱えない。本研究の初版は、席数・収容人数と開催予定が定義できる
**劇場・ライブホール・シネマ等の座席型施設**とする。

- 劇場・ライブホール: 席数×公演ごとの実入場率
- シネマ: スクリーン別席数×上映回数×上映別実入場率
- 博物館・展示型: 年間入館者÷開館日数を基準とする別モデル
- 遊園地・テーマパーク: ゲート実績と類似施設需要を使う別モデル

これらを「エンタメ」という名称だけで合算しない。

### 3.2 座席型施設の基本式

日 `d` に開催されるイベント集合を `E_d` とする。

```text
N_event(d) = N_non_event(d)
             + sum[e in E_d] capacity(e) × attendance_rate(e)
```

チケット販売率しか得られない場合は、実際に来場しない人を分ける。

```text
attendees(e)
  = capacity(e) × ticket_sales_rate(e) × show_up_rate(e)
```

シネマでは、各スクリーン・上映回について足し上げる。

```text
N_cinema(d)
  = N_non_screen(d)
    + sum[screen s, showing h] seats(s) × attendance_rate(s,h)
```

複数ホールを持つ場合も、ホール・公演単位で計算してから同時開催分を合算する。

### 3.3 通常日と開催日を混ぜない

人流への影響は平均日より公演開始・終了前後の集中が重要である。少なくとも次を別シナリオにする。

| シナリオ | 算定方法 | 用途 |
|---|---|---|
| 非開催日 | 非公演利用の類似施設実績 | 通常時の基準 |
| 標準開催日 | 標準的な公演本数・実入場率 | 代表日の比較 |
| 満席・大型開催日 | 許容収容人数に近い実績 | ピーク交通の検証 |
| 年平均 | 年間総入場者÷営業日 | 施設経営規模の比較。ピーク交通には使わない |

例えば2,000席、1公演、実入場率80%なら1,600人/公演となるが、80%は例示用の仮定であり、
対象施設の予測値には類似施設の実績分布を使う。

### 3.4 本研究での校正

類似施設を、収容人数、ジャンル、駅接続、都市規模、公演本数、料金帯で3件以上選び、次を集める。

1. 公演・上映ごとの販売可能席数
2. 実入場者数または実入場率
3. 年間開催本数と非開催日数
4. 主催公演と貸館公演の構成
5. 通常日・標準開催日・大型開催日の来場実績

公演内容により需要差が大きいため、一つの平均稼働率だけで全公演を予測しない。ジャンル、曜日、
開演時刻、料金帯、出演者規模等に条件付ける。企画が未定の計画比較では、類似施設の公演構成を
テンプレートとして低位・基準・高位を作る。

### 3.5 根拠と限界

- 国交省「大規模開発地区関連交通計画マニュアル」は、イベント施設を特殊用途とし、席数相応の
  需要を類似事例から予測するよう示す。
- 文部科学省「社会教育調査」は、300席以上の劇場・音楽堂等について、施設・設備、主催・共催事業の
  実施件数、入場者・参加者数を収集する。類似施設の公演当たり入場者を作る基礎になる。
- 同調査は主として舞台芸術施設が対象で、シネマ、ライブハウス、テーマパーク全般の標準原単位ではない。
- 未発表の出演者や演目の需要を精密に予測することはできないため、計画段階ではシナリオ予測になる。

### 3.6 Pseudo-PFLOWへの接続

目的400（自由行動）を基本候補とする。公演開始前の到着と終演後の出発をハード条件にし、既存の
自由行動を置換するモデルと、新しいイベント活動を挿入するモデルを分ける。イベント来場者数を
24時間へ平準化せず、開場・開演・終演時刻から時間帯別流入出を生成する。

## 4. 3施設を比較可能にする共通処理

### 4.1 最終比較単位

```text
external_arrivals(d)
  = 日dに施設外から新たに到着するユニーク人物数
```

| 施設 | 元統計 | 外部到着者への変換 |
|---|---|---|
| 商業 | 来店回数 | 同日複数来店率でユニーク人物数へ変換。両方保存 |
| ホテル | 人泊 | 平均連泊数でチェックイン人数へ変換 |
| エンタメ | 入場者 | 同日複数公演・複数用途の重複を控除 |

### 4.2 複合施設の重複控除

商業、ホテル、エンタメが同じ建物に入る場合、用途別人数をそのまま足さない。

```text
N_unique
  = N_retail_unique + N_hotel_external + N_entertainment
    - N_retail_hotel_overlap
    - N_retail_entertainment_overlap
    - N_hotel_entertainment_overlap
    + N_three_way_overlap
```

重複率は類似複合施設の回遊調査または同一人物の活動系列から推定する。重複率が未取得なら、
用途別訪問回数と外部来訪ユニーク人数を別々に報告し、推測で一つにまとめない。

### 4.3 低位・基準・高位

| 施設 | 低位 | 基準 | 高位 |
|---|---|---|---|
| 商業 | 類似施設の補正倍率下位 | 公的原単位×類似施設の代表補正 | 類似施設上位・開業期 |
| ホテル | 閑散期の`o,g,L` | 年間・同種ホテルの代表値 | 繁忙期の`o,g,L` |
| エンタメ | 非開催・小規模開催 | 標準開催日 | 満席・大型開催日 |

同じ±20%を全施設へ与えない。幅の原因を、稼働率、連泊数、公演本数など解釈可能な入力値で示す。

## 5. 現時点の到達点と未確定事項

| 施設 | すでに決められること | 予測値確定に必要なもの |
|---|---|---|
| 商業 | 公的式、20,000m²の基準22,000来店/日 | 実際の小売店舗面積、類似駅型商業3件、平休日補正、同日複数来店率 |
| ホテル | 客室数・稼働率から人泊、連泊数からチェックインへ変換 | ホテル種別、客室数、`g`、`L`、宿泊目的構成、外来飲食・宴会需要 |
| エンタメ | 席数×公演別実入場率、公演日別に予測 | エンタメ種別、席数、年間開催予定、類似施設3件、実入場率、非公演利用 |

したがって、方法は3施設とも定義できているが、人数の確定値はまだ出せない。次に決める入力は、
**商業の小売店舗面積、ホテルの客室数・種別、エンタメの種類・席数・標準開催日程**である。
