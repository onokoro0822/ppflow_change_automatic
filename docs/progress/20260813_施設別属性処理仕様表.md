# 集計前に確定する施設別属性処理仕様表

作成日: 2026-08-13 JST

## 0. 結論

集計やトリップ変更を先に行わず、最初の比較対象を次の3種類に固定する案とする。

- A: 名古屋駅接続の駅型商業施設
- B: ビジネスホテル
- C: 都市公園・滞在型広場（初期値は地区公園を参照）

この3種類は、人数の規模変数、来訪者属性、滞在の時間尺度、トリップチェーンの変更方法が
互いに異なる。比較することで、「施設用途の違いを個人別人流へどう反映したか」を明確にできる。

現段階で固定するのは、**計算式、属性区分、処理方法、出典の優先順位**である。類似施設データが
未取得の項目について、割合を仮に作って集計しない。

## 1. 3施設の比較表

| 項目 | A 駅型商業施設 | B ビジネスホテル | C 都市公園・滞在型広場 |
|---|---|---|---|
| 仮規模 | 小売店舗面積20,000m² | 500室 | 地区公園相当 |
| 数える対象 | 1日の来店回数。ユニーク人数とは分ける | 宿泊人泊、チェックイン人数、滞在者数を分ける | 入園者・滞在利用者。単なる通過者は除外する |
| 人数推定式 | `N_visit=A(S)×S` | `G_night=R×o×g`、`N_checkin=G_night/L` | 同種公園の日入園者実測を基準に、面積・誘致圏・駅前性で補正 |
| 式の変数 | `S`: 小売店舗面積（千m²）。名古屋市商業地区で `S<20: A=1500-20S`、`S>=20: A=1100` 人/千m² | `R`: 客室数、`o`: 客室稼働率、`g`: 1利用客室当たり人数、`L`: 平均連泊数 | `N_ref`: 同種公園平均。補正係数は類似公園3件以上で校正 |
| 現時点の基準値 | 22,000来店/日 | `500×0.754×g` 人泊/日。`g`と`L`が未取得なのでチェックイン人数は未確定 | 地区公園平均: 平日730人、休日1,009人/日 |
| 年齢の基本区分 | 0–19、20–29、30–49、50–69、70歳以上 | 同左。国内出張・業務層、国内観光層、外国人層を分ける | 原資料の学齢前、小1–3、小4–6、12–18、19–64、65歳以上を保持 |
| 年齢分布 | 愛知の目的100基準構成×類似駅型商業のFCPI。30–49歳男女は主要層だが、ハード抽出条件にはしない | 国内出張・業務層の初期分布は 0–19: 2.7%、20代: 12.4%、30–49: 35.6%、50–69: 44.0%、70+: 5.2%。他層へ流用しない | 平日: 8.5、4.0、2.6、11.5、50.9、22.6%。休日: 9.9、7.5、5.5、5.3、54.4、17.5% |
| 滞在時間の定義 | 到着推定時刻から同一系列の次トリップ出発時刻まで | 連泊数、チェックイン時刻、チェックアウト時刻。日跨ぎで扱う | 入園から退園まで。通過時間を混ぜない |
| 滞在時間の初期区分 | 30分未満、30–60分、60–120分、120分以上 | 1泊、2泊、3–4泊、5泊以上＋チェックイン/アウト1時間帯 | 30分未満、30–60分、60–120分、120分以上 |
| 現在使える滞在根拠 | Liu氏らでは商業利用の30–120分への集中を確認。割合は類似施設またはPT集計後に確定 | 平均連泊数と時刻分布は未取得。宿泊旅行統計の延べ・実宿泊者から `L=延べ/実` を計算可能 | 地区公園の平均在園時間は平日1.04時間、休日1.80時間。分布は同調査または類似公園で校正 |
| Pseudo-PFLOW候補 | 品質適用済み、目的100、年齢結合済み、営業時間・チェーン成立 | 既存目的コードだけで宿泊を表さない。出張500等を起点に日跨ぎ宿泊活動を新設 | 品質適用済み、目的400。滞在利用と判定できる候補 |
| 初版のチェーン処理 | 既存買い物目的地と次トリップ出発地を置換 | 宿泊到着、宿泊滞在、翌日出発を挿入。24時間1日データの単純置換はしない | 自由行動目的地の置換。新規立寄りは別の挿入モデル |
| 現時点の実装可否 | 類似施設分布と年齢付き母集団を取得後に実装可能 | 日跨ぎデータ構造の追加後 | 通過者定義と類似都心公園の確認後 |

### 数値の読み方

- 商業施設の22,000は、公的原単位による外部推定値であり、現計画の確定値ではない。
- ホテルの `500×0.754×g` は人泊/日の推定である。平均連泊数 `L` で割らずに新規来訪者数と呼ばない。
- 公園の730・1,009人は全国の地区公園調査の平均であり、駅前広場へ直接適用する確定値ではない。
- 年齢割合は構成比であり、特定年齢以外を候補から落とす条件ではない。

## 2. 属性ごとの処理仕様

### 2.1 来訪者人数

3施設で共通の「床面積当たり人数」を使わない。

```text
A 商業:
N_visit = A(S) × S

B ホテル:
G_night   = rooms × room_occupancy × guests_per_occupied_room
N_checkin = G_night / mean_length_of_stay

C 公園:
N_visit = N_reference_park
          × area_adjustment
          × catchment_adjustment
          × station_centrality_adjustment
```

公園の3補正係数は全国平均から任意に決めない。用途・面積・都心立地が近い3施設以上で観測された
入園者数を使って推定し、取得できなければ地区公園平均を「参照値」のまま示す。

低位・基準・高位は、根拠なしの一律±20%ではなく、類似施設間の最小値・加重平均・最大値、または
推定パラメータの信頼区間から作る。資料が揃う前は幅を確定しない。

### 2.2 年齢

候補トリップ `i` の年齢・性別セルを `c`、愛知県の同目的母集団構成を `b_A(c)`、類似施設の
相対選好を `r_f(c)` とする。

```text
q_f(c) = b_A(c) × r_f(c) / sum_k[b_A(k) × r_f(k)]
n_f(c) = N_f × q_f(c)
```

処理は次の順に固定する。

1. 年齢・性別は人物マスタに格納し、同一人物の全トリップへ同じ値を結合する。
2. 施設用途に対応する目的コードだけで愛知の基準構成 `b_A(c)` を計算する。
3. 類似施設の構成を参照地域の母集団構成で割り、相対選好 `r_f(c)` を計算する。
4. 上式で名古屋向け目標構成を作る。
5. rakingで年齢、性別、時間、距離、交通手段を同時に合わせ、人物単位で非復元抽出する。

商業の30–49歳は「主要リーチ層」であり、全員を30–49歳にする意味ではない。ホテルは、
ビジネスホテルという施設区分だけで宿泊客全員を出張者にしない。最低でも国内出張・業務、国内観光、
外国人の3層に分け、それぞれの人数と年齢分布を作ってから合成する。

公園は公式資料と共通年齢階級が一致しない。65歳以上を65–69歳と70歳以上へ分ける場合などは、
愛知の目的400候補内の条件付き比率で按分し、元の65歳以上合計は必ず保存する。

### 2.3 滞在時間

商業・公園の滞在時間は、変更後目的地への到着推定時刻と、同じ分析系列の次トリップ出発時刻から
計算する。

```text
t_arrive_new(i) = t_depart(i) + route_travel_time(origin(i), facility, mode(i))
dwell(i)        = t_next_depart(i) - t_arrive_new(i)
```

- `dwell(i) <= 0`、営業時間外、空間的に不連続な系列は候補から除外する。
- 次トリップがない場合の滞在は右打切りであり、終日滞在と決めつけない。
- 初版の滞在分布合わせは、連続する次トリップがあり正確に計算できる候補で行い、除外数を報告する。
- 施設別の目標ビンへ一致する候補を選ぶ。先に人物を抽出してから、前後活動を無視して滞在時間を上書きしない。
- 目標割合が未取得なら、既存の愛知県類似施設の分布を基準ケースにし、Liu氏の30–120分は妥当性確認の範囲として使う。

ホテルは上式を使わない。宿泊は日跨ぎ活動として、次の3分布を別々に設定する。

```text
P(length_of_stay)
P(checkin_hour | purpose, day_type)
P(checkout_hour | purpose, day_type, length_of_stay)
```

平均連泊数は `延べ宿泊者数 / 実宿泊者数` で計算する。現在の24時間Pseudo-PFLOWだけで翌日出発を
接続できないため、ホテル案の集計・変更は日跨ぎ人物データを作るまで実行しない。

## 3. 集計前に固定するデータ表

各目標値は次の形式でCSVまたはSQLiteへ保存し、コードへ直接書かない。

| 列 | 内容 |
|---|---|
| `scenario_id` | A、B、Cと低位・基準・高位 |
| `facility_type` | station_retail、business_hotel、urban_park |
| `day_type` | weekday、holiday、event_day |
| `population_stratum` | domestic_business、domestic_leisure、foreign等 |
| `dimension` | visitor_total、age、sex、dwell、arrival、departure等 |
| `condition` | 目的、年齢、距離帯等の条件 |
| `category` | 年齢階級、滞在時間階級等 |
| `target_share` | 目標構成比。未確定なら空欄 |
| `target_count` | 総人数から計算した人数。未確定なら空欄 |
| `estimate_type` | observed、official_unit、calculated、scenario_assumption |
| `source_id` | 出典ID |
| `source_year` | 資料年 |
| `source_geography` | 対象地域 |
| `sample_size` | 元資料の母数 |
| `is_fixed` | 教授確認済みか |
| `notes` | 単位、限界、按分方法 |

## 4. 集計開始のゲート

次が全て確認できるまで、A・B・Cの結果値を作らない。

| 確認項目 | 現状 | 次の作業 |
|---|---|---|
| 3施設の用途と仮規模 | 提案済み、未確認 | 教授確認 |
| 来訪数の数え方 | 本文で定義 | 延べ来店とユニーク人数のどちらを出力するか確認 |
| 平日・休日 | 分離する方針 | 各案で対象日を確認 |
| 商業の完全な年齢分布 | 未確定 | 年齢付き愛知県母集団＋類似駅型商業3施設を取得 |
| ホテルの宿泊層別人数、`g`、`L` | 未確定 | 宿泊旅行統計または類似ホテル実績から取得 |
| 公園の駅前性補正 | 未確定 | 都心・駅近の類似公園3施設を選定 |
| 商業・ホテルの滞在分布 | 未確定 | 類似施設またはPTから数値化 |
| 公園の滞在 | 平均のみ取得 | 同じ公園種別の分布を取得、平均1.04/1.80時間で検算 |
| 候補トリップ処理 | 本文で定義 | 候補数不足と右打切り件数を事前集計 |

## 5. 教授へ確認する内容

1. 比較する3施設を、駅型商業、ビジネスホテル、都市公園・滞在型広場としてよいか。
2. 仮規模を、商業20,000m²、ホテル500室、地区公園相当としてよいか。
3. 商業案は30–49歳を主要層とするが、全年齢を目標構成で配分する考え方でよいか。
4. ホテル案を国内出張・業務だけのケースにするか、観光客・外国人を含む現実的な混合ケースにするか。
5. 公園案では単なる通過者を来訪者数に含めず、滞在利用者だけを人流変更対象としてよいか。
6. 上記の未取得欄を埋めてから集計・実装へ進む順序でよいか。
