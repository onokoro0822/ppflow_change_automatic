# 商業量とPT分布の自動探索（2026-10-14 JST）

## 本人指示と実装

サイド会話で、商業量を探索し、各候補でcapacityを目標到着件数に合わせ、PT直前活動地分布とのずれを最小にする処理を依頼された。
新規 `pflow_commercial_distribution_search.py` が既存 `pflow_joint_target_calibration.py` を逐次実行する。既存の校正・Java・共有進捗ファイルは本体で修正中のため変更していない。

- 既定の商業量増分は745.943、1500、3000、6000、12000。雇用予測値ではなく校正パラメータ。
- 各増分でcapacityを最大5回調整。人数誤差±10%を満たす候補だけで愛知県内条件付きPTのTVDを比較する。
- 最良候補の左右の商業量の中間値を追加し、既定2段階で探索する。探索範囲内の最良観測値であり、大域最適性を保証しない。
- 人数の適合候補がなければ `best[target] = null`。TVD閾値0.15未達を人数適合と混同しない。
- 全試行、実行コマンド、PTハッシュ、選択結果を `report.json` に保存。全目標の人数適合候補がある場合だけ、全数確認用 `selected_pilot.json` を保存する。
- 既存エンジンまたはPT入力が探索中に変わった場合は停止し、異なる条件の結果をまとめない。

## 確認した範囲

`.venv/bin/python -m unittest discover -s tests` で128テスト成功（新規8件を含む）。新規テストは人数制約の優先、未達の明示、段階探索、参照上限の換算、疑似実行によるレポート連携、失敗記録、上書き拒否を確認した。
人流生成・3000/6000件の新規探索は未実行。本体の修正後校正と競合するため、この会話では長時間生成を開始していない。
活動完全固定、PT適合、区外店舗からの転換増はこの実装で確認した結果ではない。

## 実行方法

本体の生成とJavaコンパイルが終わってから、新しい出力先で実行する。1 JVM、最大6GBを既存エンジンが使用する。最初の5増分×2目標に追加探索が続くため、単一ケースより時間がかかる。
`--baseline` は同一seed・標本率・モデル設定の施設なし出力を指定する。以下のパスは既存エンジンの既定参照であり、修正後モデルとの対応は実行前に確認する。

```bash
.venv/bin/python pflow_commercial_distribution_search.py \
  --pt-csv ../中京PTデータ/chukyo_pt_2022_od_d5_shopping_facility_age.csv \
  --targets 3000 6000 \
  --baseline .local/pflow/output/large_store_20261014/p2d045/seed42/baseline \
  --output .local/pflow/output/commercial_pt_search_20261014 \
  --stages 2 --capacity-rounds 5
```

探索後、選択した商業量を固定して全数の人数を再校正する場合:

```bash
.venv/bin/python pflow_joint_target_verify.py \
  --pilot-report .local/pflow/output/commercial_pt_search_20261014/selected_pilot.json \
  --output .local/pflow/output/commercial_pt_search_20261014_full_check \
  --run-output-root /Volumes/PFLOW_SSD/PFLOW/output/commercial_pt_search_20261014_full_check
```

全数確認は選んだ商業量での人数修正であり、全数で商業量を再探索する処理ではない。PT適合は全数結果から改めて判断する。既存全数確認コードの分布閾値は0.15固定。
参照上限122件は既存エンジンの修正後2%・seed42設定に依存する。別seed・モデル条件では測り直して `--reference-ceiling`、`--reference-sample-factor`、`--reference-addition` を指定する。初期容量のための近似値であり、生成結果の到達可能性の証明ではない。
