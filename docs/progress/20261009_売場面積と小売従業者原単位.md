# 売場面積から小売従業者数への変換（2026-10-09 JST）

## 確認結果と暫定設定

NEXTの項目1を実施。指定された `../関連資料/y671401000.xls` は、日本統計年鑑（第67回・平成30年）
表14-1「卸売業・小売業の事業所数，従業者数，年間商品販売額及び売場面積（平成24,26年）」だった。
引き継ぎに書かれた「百貨店・大型総合スーパーの表」ではない。シート `y1401000` のF20は小売業全体の従業者数、
H20は売場面積で、A22の注記は売場面積を回答のあった事業所に限定している。小売全体の総従業者数を割った値は採用しない。

同じ年鑑の[表14-5（業態別表）](https://www.stat.go.jp/data/nenkan/67nenkan/zuhyou/y671405000.xls)を取得し、
全国・2014年7月1日の大型百貨店を、旧本店と同じ業態・規模区分を使う暫定基準とした。
将来施設の雇用者数を検証した値ではなく、【仮】大型百貨店の全国比率を計画に移植するシナリオである。

| 業態 | 従業者数（人） | 売場面積（千㎡） | ㎡/人 | 54,374㎡相当の従業者（人） |
| --- | ---: | ---: | ---: | ---: |
| 百貨店全体 | 66,683 | 4,762 | 71.4125 | 761.4073 |
| 大型百貨店（暫定基準） | 65,068 | 4,743 | 72.8930 | 745.9430 |
| 総合スーパー全体 | 265,956 | 12,547 | 47.1770 | 1,152.5537 |
| 大型総合スーパー（業態感度候補） | 243,544 | 11,982 | 49.1985 | 1,105.1962 |

元セルはシート `y1405000` のE11/G11、E12/G12、E14/G14、E15/G15。G列は千㎡（G8）。
全行の転記をxlrdで原本と突合した。表14-5は管理・補助活動のみ、分類不能、小売販売額なしの事業所を除く（A4）。

式: `追加従業者 = 計画の売場面積㎡ × 統計の従業者数 / (統計の売場面積千㎡ × 1000)`。
大型百貨店は `54,374 × 65,068 / 4,743,000 = 745.942954248366人`。
面積は現行計画の比較用売場面積相当で、新計画の延床面積ではない。
複合用途に展開するときは商業へ配分した売場面積相当だけに掛ける。

## 定義と適用上の限界

- [平成26年商業統計の用語説明](https://www.meti.go.jp/statistics/tyo/syougyo/result-4.html)では、従業者は個人業主・無給家族従業者・有給役員・常用雇用者の計。
  臨時雇用者を除く。一方、[平成28年経済センサスの調査票記入資料](https://www.stat.go.jp/data/e-census/2016/pdf/shikata2.pdf)では従業者に臨時雇用者を含む。
  よってモデルの従業者数と厳密には一致しない。年度・地域・業態の移植に加え、この定義差も残る。
- 就業者（出向・派遣の受入・送出調整後）や8時間換算従業者、日来訪者数とは別物。
  売場面積の統計は施設全体のテナント従業者を必ず全て含む保証もなく、新施設への完全一致とは説明しない。
- 低位・基準・高位の統計的な信頼区間は作らない。大型総合スーパーは業態違いの感度候補である。
- 旧施設を含むbaselineへの純追加を仮定する既存実験を継承。旧施設を除いた再開発差分は未実装であり、純増雇用の実測ではない。
- Pseudo-PFLOW `DataAccessor.loadEconomicCensus` はCSVの先頭2列以降をeconomicsへ格納し、
  `ActGenerator.getMeshCapacity` の買物はindex 4、`CapacityScenario.apply` は
  `before × meshCapacityMultiplier + meshCapacityAdd` を適用する。今回Javaは変更していない。
  メッシュの加算従業者数と、施設選択の相対重み `facility.capacity` は別の量。
- 2%標本だからといってメッシュ加算従業者を50分の1にはしない。人数標本化と入力特徴量を区別する。

## 項目4の調査中に発見した推定とJavaの不整合

`pflow_mnl_estimation.load_cities` は、メッシュを最初に読んだ行政界へだけcapacityを加えていた。
一方、Javaの `DataAccessor.loadEconomicCensus` は最初の有効行政界行の値を共有GMeshへ保存した後、
後続の行政界にも同じGMeshを登録する。`City.addMesh` は区内の重複を除き、
`ActGenerator.configureShoppingAttraction` は各区に登録された全メッシュを足す。

実データ再集計で、旧PythonとJava相当の差を確認した。

| 行政界 | 旧Pythonの従業者capacity合計 | Java相当の合計 |
| --- | ---: | ---: |
| 西区23104 | 38,718 | 79,028 |
| 中村区23105 | 5,101 | 73,260 |

これは行政界の実従業者数そのものではなく、境界メッシュを共有するモデルの特徴量である。
同じメッシュを複数区に含めるJavaの仕様を変えず、Python側を一致させた。
県外が先頭となる共有メッシュ・無効行政界・同一区内重複行も含めた回帰テストを追加。
実データの愛知69市区町村すべてでJava相当の集計と一致した。全Pythonテスト94件成功。
Javaのコード・既定動作は変更していない。

修正後の再推定コマンド:

```bash
.venv/bin/python pflow_mnl_estimation.py --attraction ln_wholesale_retail_employees \
  --output-dir output/retail_floor_area_20261009/shared_mesh_mnl
```

「β・距離・行先魅力」の推定結果:

- β=0.40625、距離倍率0.90625、面積倍率-0.0625、人口比倍率-4.65625、オフィス比倍率-0.453125。
- 対数尤度-1,612,662.4052、行先TVD0.06211785、中村区出発地TVD0.21766314。
- これらはPTへの当てはまり（推定内の値）であり、Pseudo-PFLOW生成結果の検証値ではない。
- βのみでは-0.13671875。正の商業量効果は、行先の既存説明変数も合わせて推定した場合の結果。

修正後βで745.943人を足しても、中村区の正規化前の選択重みは約0.4124%しか増えず、
西区も同じ共有メッシュを持つため約0.3824%増える。選択確率の増加率そのものではない。
区間流入の変化が小さい理由として、集計量に対する追加量の小ささと、隣区への同時反映がある。
大型施設ダミーや施設規模別指標を導入する場合は、全行政界で同じ定義の説明変数を作り直して再推定が必要。
施設の実測ODが未取得なので、新しい指標の効果を未検証のまま採用しない。
