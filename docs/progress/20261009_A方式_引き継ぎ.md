## 1. いまの到達点

- 最終目標はA（Pseudo-PFLOWのモデルを改良し、施設のcapacity変更だけで人流を変える）。Bは比較対象（DECISIONS.md 2026-10-09）。
- Pseudo-PFLOW-v3（`../Pseudo-PFLOW-v3`、ブランチ`feature/capacity-scenario`、push先`mine` = github.com/onokoro0822/Pseudo-PFLOW-v3 非公開）に次を追加済み。
  いずれも既定値では従来出力と207 CSVがバイト単位で一致することを確認済み。
  - `--shopping-attraction-beta β`: 買物の行先市区町村MNLに`β × ln(1 + 市区町村内メッシュの買物capacity合計)`を追加
  - `--shopping-mnl-multipliers 距離,面積,人口比,オフィス比`: 研究室の買物MNL係数に倍率をかける
  - `--shopping-local-mesh-capacity log|raw`: 区内のメッシュ選択を`log(1+cap)/距離^β`（従来）か`cap/距離^β`にする
  - scenario JSONの`meshCapacityAdd`: 跡地メッシュの買物capacityに足す量（計画で増える小売従業者数）
- 買物capacity列は`mesh_ecensus.csv`の`t000917029`＝平成28年経済センサス活動調査1kmメッシュ「I 卸売業，小売業」従業者数（e-Stat定義表で確認）。

## 2. 現在の採用設定（推定MNL＋区内raw）

```
--shopping-attraction-beta 0.188 --shopping-mnl-multipliers 0.906,0.0,-2.797,-0.094 --shopping-local-mesh-capacity raw
```

- 係数は`pflow_mnl_estimation.py`の「β・距離・行先の魅力」推定（卸売小売従業者版）。小売店数版はβ=0.438、倍率0.898,-0.125,-3.844,-0.5。
- シナリオ: `config/pflow_capacity/plan_add{1500,3000,6000}_f8000000.json`（メッシュ倍率1、従業者を足す、施設capacity 800万）。
- 結果（愛知県2%・seed 42）: 施設到着346〜378件、出発地TVD 0.36〜0.37、中村区内33〜34%、中村区の買物895→898件（他地区からの流入はほぼなし）。

## 4. 再現手順

```
cd ppflow_change_automatic
# Java を変更したら必ずコンパイルし、実行ログでエラーがないことを確認する（下記の注意参照）
(cd ../Pseudo-PFLOW-v3 && mvn -q -DskipTests compile)
H=$PWD/.local/pflow
EST="--shopping-attraction-beta 0.188 --shopping-mnl-multipliers 0.906,0.0,-2.797,-0.094 --shopping-local-mesh-capacity raw"
bash scripts/run_pflow_capacity_sweep.sh --scenario baseline --seed 42 --skip-compile --pflow-args "$EST" --output-root $H/output/estimated_mnl/raw
bash scripts/run_pflow_capacity_sweep.sh --scenario-file config/pflow_capacity/plan_add3000_f8000000.json --seed 42 --skip-compile --pflow-args "$EST" --output-root $H/output/estimated_mnl/plan
.venv/bin/python pflow_mnl_estimation.py --attraction ln_wholesale_retail_employees   # 係数の推定（1秒程度）
.venv/bin/python -m unittest discover -s tests                                         # 全テスト
```

集計は`pflow_capacity_analysis.summarize_scenario`（施設・メッシュ・区の到着数）と`pflow_origin_comparison.pflow_origin_counts`
（施設来訪者の出発地、PT参照との比較）を使う。1回の実行は約8分。

## 5. 作業上の注意（実際に起きたこと）

- `mvn compile`はJavaのコンパイルエラーがあっても成功扱いで終わることがある。実行ログ（`<output-root>/<scenario>/logs/*.log`、
  スクリプトの標準出力）に`Unresolved compilation problems`が出ていないか必ず確認する。
- Javaファイルの多く（ActGenerator, Commuter, NonCommuter, Student）は改行がCRLF。LFで書き戻すと全行差分になる。
- オプションを追加したら、既定値で従来baseline（`.local/pflow/output/capacity_experiment/baseline/23`）と`diff -rq`で完全一致を確認する。
- 跡地メッシュ52366700は西区23104と中村区23105の両方に属する。施設行の行政界コードは選ばれた市区町村で、店舗の所在とずれることがある。
- 外付けSSDは「ゆうき」フォルダ以外に触れない。イメージは日本語パスだとマウントできないため、英字のシンボリックリンク経由で`hdiutil attach`する。
